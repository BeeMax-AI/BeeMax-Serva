# MCP AI 相对日期查询差异

验证时间：2026-09-06，工作台时区 Asia/Shanghai。

## 复现

调用 `chat`，新会话，无 report_id：

```json
{
  "message": "请查询昨天新建和闭环的工单数量，简短回答，并说明数据范围。不要执行业务操作。",
  "context": {"page": "insights"}
}
```

实际回答新建 0、闭环 0，并声称“昨天无任何工单产生或闭环”；`data_coverage` 为“已查询：get_report。”。

同期调用 `create_analysis`，start_date/end_date 均为 `2026-09-05`、timezone `Asia/Shanghai`、scope `all`，完成后 `get_analysis` 返回：

- created：31，按报单日计入。
- closed：34，按关单日计入，可能包含区间前工单。

携带该报告的真实 report_id 调用 chat，询问“根据当前引用的2026-09-05分析报告，这一天新建、闭环分别多少单”，正确返回 31 / 34。

## 请 MCP Server 侧排查

1. 检查首次 chat 内部调用 get_report 的实际日期、kind 和时区，是否正确把“昨天”解析为 2026-09-05。
2. 核对 get_report 和分析任务对新建、闭环的口径是否一致。
3. 缺少记录或报表查询为空时，不要直接声称业务量为零。
4. 回答中返回明确的起止日期、时区、查询工具和指标口径，使前端能核对依据。
5. 补相对日期、明确日期、报告追问三条路径的一致性测试。

以上是实测差异，尚不能仅凭前端结果确定是日期解析还是报表数据来源问题。平台原样显示工具回答，未把空值填成零。接口接通、报告生成及报告追问均已验证；自由问答的数字准确性不能据此全部验收。
