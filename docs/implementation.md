# 实现范围与验收

依据：`design/gongdan-dashboard/设计说明.md` 和用户本次指令「先实现前端、后端，后续提供 MCP Server 对接数据库」。保留现有工单运营功能，不增加会话中心、知识库或其他底座产品模块。

当前为可运行的本地全栈应用，不是已接入客户数据库的生产系统。原设计稿保留；浏览器从 Node API 获取真实持久化的本地记录。UI 维持千蜂智服品牌、顶部 AI智能分析、连接管理分组和全局浮动 AI助手。

## 范围

实现入口和说明见 README。核心边界：

- `shared/domain.ts`：规范化客户数据、配置、工单、消息、分析和会话类型。
- `server/src/provider.ts`：后端本地提供器、校验、幂等、版本冲突及 MCP 待接入边界。
- `server/src/http.ts`：会话、角色、同源检查与 API。
- `server/src/store.ts`：仅用于本地开发的 SQLite、账号及加密凭据保存。
- `server/src/ai.ts`、`dates.ts`、`metrics.ts`：真实记录聚合、可选模型、周期调度与报告保存。
- `client/src/`：数据驱动的前端页面、操作确认和浮动助手。

前端分组和名称由客户数据提供；用户/租户和审计操作人只从后端会话取值。未配置 MCP 不访问原规格中的网络地址。界面没有切换 owner 角色的设计预览按钮。

### 独立 QiWe 连接配置

设置中分别保留「QiWe 连接」与「MCP 数据连接」。`GET /api/qiwe/connection` 返回已保存字段、脱敏账号、更新时间、独立版本号；`POST` 使用 `expectedRevision` 更新凭据，留空保留旧值，运营管理员（admin）及平台管理员（owner）均可修改，只读账号不可修改。接口在读取业务数据源之前处理，因此不依赖 MCP 工具、业务数据版本或 MCP 可用性。凭据沿用服务端 AES-256-GCM 加密存储，操作记录只记动作，不记录内容。

当前未提供 QiWe API 地址、鉴权及连接检测协议，因此仅实现凭据管理；页面始终明确显示「未验证」，检测按钮不可用。后续拿到 QiWe 文档后接独立服务端适配器，不通过工单 MCP 修改 QiWe 配置，也不把本地保存成功当作远端连接成功。

### 企微连接管理设计稿迁移

2026-09-06：依据 `design/gongdan-dashboard/connections.js` / 8765 的企微账号页，将连接管理作为独立配置模块迁入正式应用。

| 设计稿功能 | 正式平台实现 |
| --- | --- |
| 添加企微账号、管理实例 | 名称、所属空间持久化；只由服务端设置待连接/未登录状态 |
| 账号筛选、Agent 详情 | 账号列表与详情互通，保留 20/30 条分页 |
| 主动推送群名单 | 按实例添加、移除 chat_id 与群名；配置保存，通道接入后才能生效 |
| 消息日志 | 实例/方向/类型/状态/关键词筛选、详情、分页、15 秒独立刷新；当前无真实通道消息 |
| 连接设置 | 进入独立 QiWe 凭据页面；返回企微账号，保持真实角色权限 |
| 操作记录 | 连接配置审计合并展示到工作台变更记录 |

`GET /api/connections`、`POST /api/connections/commands` 均在业务数据源调用前处理，SQLite `wecom_connections` 按登录租户隔离，独立版本号与请求幂等控制。账号/群配置允许运营管理员及平台管理员修改，只读账号不能写入。初始为空，不将设计稿的酒店名称、示例账号、模拟在线状态或消息当成正式数据。旧本地开发数据提供器的账号/消息字段不作为此模块的数据来源。

连接刷新使用专属事件，不中止或重置 MCP 同步；较旧的连接或工作台响应不能覆盖已保存的新连接配置。企微登录、真实在线检测、主动推送执行和消息接收仍待 QiWe 服务契约接入，当前界面明确显示待连接/待同步。

迁移验证：81 项测试、类型检查和客户端构建通过。隔离浏览器验证新增账号、推送群保存、刷新后保留、配置页联动与消息日志筛选入口；回归覆盖两种数据模式的独立保存、租户/只读权限、重复提交、配置版本冲突和过期响应保护。

2026-09-06：按用户要求开放 QiWe 凭据编辑给运营管理员，与平台管理员共用同一保存权限；只读账号仍由服务端拒绝。表单按参考图改为 Token / 账号 / 密码三行布局，Token 与密码可分别显示/隐藏，重置恢复隐藏状态。此变更不提升账号角色或其他配置权限。

### 2026-09-07 白名单统一归入企微账号

企微实例的 Agent 详情入口改为「白名单」，包含白名单授权（群 / 人员）、推送设置、访问权限。移除配置管理的「群与权限」「推送群设置」入口。实例群和人员授权独立持久化；推送开关仅面向已授权群，新群默认关闭推送，旧记录缺少开关时保留原有开启语义。撤销群授权同步移除该群的推送配置。

访问权限继续复用 MCP 渠道接口，明确标注整个渠道生效，不将实例授权默认为已同步；企微账号列表保留渠道权限入口，空实例时仍可操作原有 MCP 权限。新增人员及推送操作沿用后端角色、租户、版本与请求幂等检查。

验证：83 项测试、类型检查、构建通过；规范 / 规格双轴审查无可操作问题。隔离浏览器验证账号入口、人员添加、推送开关保存，以及桌面和窄屏布局。未变更真实群、人员权限或发送外部消息。

白名单模块进一步内嵌到企微账号列表下方，三个页签始终可见；实例选择器指定授权与推送的管理对象，账号行的白名单按钮定位到页面下方。旧 `#agent` 链接兼容显示同一账号页面。账号列表与白名单使用独立分页状态，MCP 渠道级范围保持不变。

### 2026-09-07 升级通知人员管理

排班人员页新增按小组的 L1–L4 通知名单，展示中文职责、真实升级间隔、默认/今日来源和 @所有人规则。管理员可选择默认持续名单或当前业务日期覆盖，对指定级别添加、移除人员；添加支持选择已知人员或填写真实企微 ID，移除前明确级别、对象、范围及空名单提示。人员与负载页提供直接入口。

L3 增加「编辑通知方式」，可在部门全体（@所有人）与指定人员之间切换，指定名单支持勾选已知人员及直接填写新人员。确认页对比原设置和新名单，明确默认/今日范围；L3 的广播模式仍不能用普通个人增删命令隐式修改。独立 `roster.level.save` 命令校验级别、范围、日期、人数、重复 ID 和广播 ID，通过 `set_roster` 保存完整快照；保留未变动成员元数据。93 项测试通过，真实名单未修改。
