# 千蜂智服

基于已确认设计稿的前后端应用。包含 AI 分析、运营看板、趋势、工单、人员、企微实例、消息日志、Agent 白名单、配置管理和可拉伸 AI助手。

## 本地启动

需要 Node.js 24 或更新版本。

```bash
npm install
npm run build
npm start
```

打开 http://127.0.0.1:8766。首次启动生成 `.local/access.json`，内含本机随机生成的账号密码：

- `admin`：演示客户运营管理员
- `owner`：同一客户的 owner，可保存连接凭据
- `viewer`：同一客户只读账号
- `other`：另一个演示客户的管理员，用于验证租户隔离

`.local/` 不纳入 Git。开发数据保存在 SQLite，重启或刷新会保留。客户端构建输出位于 `client/dist/`。修改前端后运行 `npm run build`；后端修改后重启 `npm start`，或使用 `npm run dev` 自动重启后端。`dev` 不监控前端构建，前端变更仍需再次 build。

原设计稿保持在 `design/gongdan-dashboard/`；8765 的原静态服务不属于本应用。

## 配置

参考 `.env.example`。应用不隐式读取 `.env`，可显式启动：

```bash
node --env-file=.env --import tsx server/src/index.ts
```

- `DATA_PROVIDER=local`：本地开发数据提供器，可持久保存写操作，但不驱动真实工单引擎、不发企微消息。
- `DATA_PROVIDER=mcp`：MCP 适配预留，当前会明确返回 503，避免误用本地数据。接口交付后按 `docs/mcp-integration.md` 实现映射。
- `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`：可选的 OpenAI-compatible Chat Completions 服务。URL 必须包含 API 前缀，例如 `https://gateway.example/v1/`。三个参数齐备时调用模型；未配置时提供数据库查询、统计与明确标记的规则建议。模型故障会返回错误，不伪装为 AI 成功。
- `HOST` 默认 `127.0.0.1`；`PORT` 默认 `8766`。外部部署要求 HTTPS 反代，设置 `APP_PUBLIC_URL` 为准确页面源、`SESSION_SECURE=true`。非本机监听时启动器强制检查这两项。

初始账号仅用于本地开发验证，当前未实现账号管理、密码轮换、多节点会话及企业 SSO。在外部部署前接入既有身份系统或补齐这些能力。所有用户权限、租户范围在后端根据会话判断，前端不能指定。

## 已实现

- 前后端 TypeScript；浏览器 ES modules，Node HTTP API，SQLite 本地持久层。
- HTTP-only Cookie 登录、12 小时会话、退出、同源写请求校验、角色与租户隔离。
- 数据驱动的小组、人员、服务对象标签、规则；列表搜索筛选分页；统计从记录计算。
- 工单详情与事件时间线；催办、转派、挂起、恢复、完成，后端校验状态、负责人和提醒时间，确认后保存。
- 路由增改删、默认人员排班、提醒参数、学习开关、白名单增删；版本冲突返回 409；请求 ID 防止重复提交；后端审计。
- 企微实例信息管理、消息日志、失败详情及关联工单；连接登录及实际通道动作等待 MCP/相关接口，界面不伪造连接成功。
- owner 连接凭据管理，AES-256-GCM 本地加密；密钥与 SQLite 分离保存，返回值和审计均不含凭据明文。演示账号的后端身份不通过前端“预览 owner”按钮切换。
- 日/周/半月/月/季/年/自定义间隔分析计划，频率与回顾范围分开；UTC+8，月末日期自动适配；后端每 30 秒检查计划；报告归档与建议跟进。
- AI助手独立会话、历史持久化、页面上下文、草稿、查询、工单入口；小窗/放大、四边四角拉伸、视口限制。当前对话仅查询，不绕过工单操作确认。

## 当前边界

- 首次启动导入 12 条明确标记的本地样例，数据量与设计稿中静态展示的 174 单不同，指标始终以实际样例为准。
- 当前本地提供器用于开发联调，不是另建一套生产工单内核。真实引擎状态变更、通知、QiWe 登录和回调由未来 MCP 适配负责。
- MCP 尚未收到端点、鉴权和完整工具契约；不会猜测工具参数、直连客户数据库或使用旧规格中的地址自动调用。
- 本地默认排班支持小组、档位、在岗；按日覆盖、专职及楼栋路由待 MCP 返回结构确定后映射，当前未伪造该功能。
- 自动分析仅在服务进程运行时执行。停机后恢复时，每个过期计划补一份到期报告，再安排下一次，不逐份补历史漏跑报告；计划执行按 runKey 去重。模型失败保留到期计划供下一轮重试。
- 自定义计划、报告与建议跟进目前存在本地提供器中。接 MCP 时需确认对应存储工具；不得默默维持两套生产数据真源。
- 数据不足会标记覆盖范围。趋势图长区间使用抽样点显示；汇总数仍统计完整查询区间。
- AI停止按钮是“停止等待”；浏览器中止等待不保证服务端或模型取消，后续刷新可看到已完成的保存结果。
- 单进程本地开发运行；尚未声明生产部署或高可用验收。未配置或联调外部模型，本轮只验证未配置模型的数据查询路径。
