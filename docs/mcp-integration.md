# MCP 接入与验收

浏览器 → 工作台 `/api/*` → 服务端 MCP 适配器 → 既有数据库与工单引擎。

2026-09-06 已验证用户提供的 HTTPS 端点，支持 HTTP JSON-RPC，协议 `2024-11-05`，最新发现 32 个工具（初次接入为 18 个）。生产端点与 token 仅保存在忽略入库的服务器配置中。初始化、会话头、JSON/SSE 响应、普通工具 20 秒及 AI 对话 90 秒超时、8 MB 响应上限、禁止重定向均由 `mcp-client.ts` 处理。错误不回传远端 URL 或原始错误内容。

## 配置

默认读取 `DATA_DIR/mcp-connection.json`（默认 `.local/`），也可设置 `MCP_CONFIG_FILE`。文件应设为 `0600`，仅供服务进程读取：

```json
{
  "url": "https://your-server.example/mcp?token=REPLACE_ON_SERVER",
  "tenantId": "your-local-tenant-id",
  "tenantName": "客户名称",
  "referenceLabel": "服务对象"
}
```

该凭据绑定一个经过配置的本地客户身份。服务端依据登录会话校验客户，其他客户账号在发出远端请求之前被拒绝。不能使用浏览器提交的 tenantId 或 by 越权访问。当前仅配置一个 MCP 数据源；更多客户需增加服务端数据源注册配置，不能共用当前客户凭据。

发现配置后自动启用 MCP；显式 `DATA_PROVIDER=mcp` 且未提供配置时返回 503。显式 `DATA_PROVIDER=local` 仅用于本地开发。认证会话仍由本工作台 SQLite 管理。

## 功能映射

| 工作台功能 | 远端工具 / 当前行为 |
|---|---|
| 工单列表、统计 | `list_tickets(limit:1000)`、`ticket_stats` |
| 正文和流转详情 | 按需 `get_ticket(id)`，列表不伪造正文 |
| 人员、小组 | `get_roster`、`get_config(groups)`；显示默认及日期覆盖排班 |
| 路由规则 | `get_routing_rules`；`set/clear_routing_rule` 和 `set/clear_subject_rule`，类型覆盖移除后恢复基础配置 |
| 全库统计 | `get_analytics`；总览、趋势、人员、AI分析页面的“全库统计”入口，源系统口径与已加载明细统计独立展示；日/周/月趋势、人员近 7/30/365 天或全部历史；列表每页 20/30 条 |
| 业务报表 | `get_report`；按日查询日报、管理员全盘报、小组早报；只查询不推送，不冒充工作台 AI 模型分析 |
| 默认档位与今日排班 | `set_roster` 保存服务端完整快照，仅调整已知默认成员档位，保留日期覆盖、专员、楼栋时段及其他人员字段；禁止直接写入 `@ALL` 广播档位。`set_on_duty_today` 设置今日一线当班人 |
| 排班原文 | `ingest_roster_text`，确认后远端解析并直接写入；不是解析预览接口。楼栋与时段可在排班页面单独查看，每页 20 条 |
| 渠道访问权限 | `get_whitelist` / `set_whitelist`，企微和飞书的私聊白名单及私聊/群聊策略。管理员可维护名单和收紧策略，仅所有者可放宽策略；保存会重启对应渠道服务。群条目只读，不等同于主动推送群授权 |
| 变更记录 | `list_config_changes(limit:1000)` 与工作台审计合并，远端配置值不回传浏览器 |
| 催办、转派、挂起、恢复、完成 | 对应 `*_ticket` 工具；人工确认后执行；可能发送真实企微通知 |
| 转派 | 仅目标小组，由远端选择处理人；不支持指定个人 |
| 派单参数 | `set_config` 的固定路径：升级间隔、接单后完成提醒、挂起提前提醒，每次一项 |
| 学习开关 | `transferLearning.autoApply`、`routingShadow.enabled`，每次一个布尔值 |
| 企微实例、消息日志、主动推送授权群、QiWe 凭据 | 本次接口没有提供，显示不可用，不使用演示数据代替 |
| 分析计划、报告、建议跟进、个人对话 | 工作台 SQLite 独立 `mcp:<tenant>` 命名空间存储，初始为空；分析读取 MCP 业务数据 |

排班中的楼栋时段、专员和 `@ALL` 不等同于个人实时在岗，本界面不据此推测在岗状态，实际分配由远端业务引擎负责。读取覆盖仅限已加载记录；接口不能分页时最多取 1000 条，数量不足会明确注明统计为部分数据。读取缓存为 10 秒；工具目录每 60 秒重新发现一次，无须重启服务发现工具变化。核心读取失败直接报错，渠道权限和远端审计读取失败单独说明，不以空结果冒充成功。

远端 `open` 字段与所有非 `CLOSED` 状态数量存在口径差异（现场 8 与 12，数据会变化）。界面保留非闭环统一口径，并同时说明远端值，不擅自将 `NO_ACCEPT` 从待闭环中移除。

## 写操作边界

服务端先校验角色、白名单动作、参数和最新远端快照版本，再提交。远端没有原子版本比较或幂等键，快照比较不能消除源系统同时写入的竞争，当前仅声明单进程联调能力。

工单工具只接收短码或房号，因此仅在已完整读取且短码唯一时提交短码，不能确认唯一性时拒绝。不会猜测完整 ID 可以放入 short 参数。提醒时间从 ISO 转换为明确 UTC+8 的 `YYYY-MM-DD HH:mm`。

提交前持久记录请求 ID 和完整命令哈希。断连、超时、工具报错或无法识别的确认结构均标记结果待核对，相同请求 ID 不再自动发送；用户须先核对源系统，避免新请求重复业务操作。目前成功确认只接受明确 `ok:true` 或 `success:true`。真实写工具的成功响应仍需在授权业务操作时验证，如结构不同应先调整确认契约，不自动重试。

仅开放固定配置路径；`clear_config`、任意路径写入、FAQ 学习等不在当前设计范围。远端配置审计最多载入最近 1000 条，不冒充完整历史。新工具仍通过明确字段映射开放，不直接允许浏览器传入任意工具名或整个排班对象。

## 验收

- 实际端点只读：初始化和工具清单、197 条工单、3 个小组、37 条小组人员关系、17 条规则、工单正文和事件。计数是验收时快照。
- 浏览器从真实后端登录后验证 MCP 模式、真实总览、详情、不可用功能提示。
- 模拟 MCP 测试覆盖 JSON/SSE、客户隔离、字段映射、工作台元数据与业务数据分离、权限/版本冲突、重复请求、结果不明防重试、短码歧义、参数映射和凭据脱敏。
- 未向真实群发送测试消息，未执行远端配置变更或工单状态写入。早期验收时未配置外部大模型；新增 AI 工具的验收见下文。

主要代码：`server/src/mcp-client.ts`、`server/src/mcp-provider.ts`、`shared/domain.ts`；回归测试：`tests/mcp.test.ts`。

## 工作台自动同步

页面顶部只保留可点击的同步状态，不展示技术性数据说明横幅。点击状态可选择每 5 分钟（默认）、每 10 分钟或自定义 1–1440 整数分钟。设置按登录用户和客户分别保存在当前浏览器；页面打开且可见时自动同步，退出登录停止计时。

同步保留筛选、分页与键盘焦点；未提交表单、编辑弹窗、输入中或助手回复中暂缓应用新数据。失败保留已有内容并显示失败状态，下个周期重试；部分数据不会显示为完整同步。此设置控制工作台页面刷新，不改变服务端分析报告计划或远端业务引擎。

## 2026-09-06 统一 AI 通道

新增并实际确认 `chat`、`create_analysis`、`get_analysis`，工具总数 32。MCP 模式中 AI助手、AI智能分析和定时分析均调用同一 MCP Server，平台不再在这些路径调用本地模型或回退成规则回答。

- `POST /api/chat`：平台要求 `requestId`，把登录用户映射为服务端生成的 `user_id`，把本地会话/报告标识转换为远端标识。当前页面、已校验工单、已归档 MCP 报告可以作为上下文；浏览器不能指定远端会话或冒充用户。旧本地报告不自动作为 MCP 报告发送。会话消息安全转义展示，同时展示返回的数据覆盖与引用文字。
- `POST /api/reports`：返回 HTTP 202 与本地任务标识、状态；起止日期覆盖日/周/月/年及自定义范围，当前页面分析全部业务（`scope:all`）。远端时区实际固定 UTC+8，平台不声明支持其他时区。
- `GET /api/analysis-tasks/:id`：查询并更新本人任务；管理员可查看计划任务。`GET /api/analysis-tasks` 返回可见任务和客户共享报告。后台每 30 秒公平轮询一批任务，前端按远端建议间隔查询；切页、刷新或平台服务重启不重建已有任务。
- 报告保留远端指标及各自统计口径、空值、发现、建议优先级和覆盖说明。结构或日期范围不匹配不归档，不用已加载工单快照或零值填补远端指标。`ai_narrative`/`fact_only` 决定 AI 或数据汇总标记。
- 数据事实与 AI 发现/推断分别展示；模型叙述和建议仍可能出错，应结合引用核对，不代表已自动执行建议。

SQLite 新增 `ai_operations` 和 `ai_conversations` 表，保存任务、幂等记录和会话标识映射。任务在网络提交前持久化，超时后重用同一个远端 request_id；同参数并发请求共享同一任务，不同参数拒绝。聊天映射、消息和请求结果同事务保存。同会话回复串行，迟到请求读取最新历史后追加。

远端 `user_id` 明确仅用于留痕，不是权限边界，因此平台后端对用户会话及任务做归属校验。客户隔离仍依赖当前凭据所绑定的远端数据范围；本平台账号的 tenantId 无法扩大范围，且 token 只保存在服务端。直接持有 MCP 凭据的客户端权限不由本平台控制。当前仍是单实例平台服务，多进程工作锁与远端 AI 服务重启恢复未做生产验收。

远端模型失败不保存伪造报告；任务保留失败状态。网络故障会在同一任务上继续查询。停止助手仅停止浏览器等待，服务端可能继续保存结果；失败重试同一问题时复用请求标识。定时任务明确失败后保留失败项并安排下一周期，不无限重复创建失败任务。

验证：新增 9 项 MCP AI 服务回归，涵盖持久化恢复、任务/会话归属、幂等与冲突、对话续接、未知结果重试、错误范围拒绝、周期计划、并发回复和轮询公平性。全套 68 项测试通过。`scripts/check-ai-ui.ts` 使用隔离接口验证任务提交、失败报告读取恢复、报告追问、空值显示和内容转义。真实联调只调用只读对话及生成分析，不执行工单/配置变更或外部消息发送。

### 远端回答质量待核对

真实页面联调中，询问“昨天新建和闭环的工单数量”时，`chat` 返回 0 / 0 并引用 `get_report`；相同业务的明确日期 2026-09-05 分析报告返回 31 / 34。平台原样展示工具返回结果，没有将空值变成零。相对日期解析或远端取数口径仍需 MCP Server 侧核对；不能把工具已接通等同于所有回答准确。

同一日期报告追问已实测正确返回 31 / 34，差异集中在未引用报告的“昨天”查询路径。可转交远端开发的复现说明见 `docs/mcp-ai-upstream-issues.md`。

## 升级通知名单编辑

在「配置管理 → 排班人员 → 升级通知设置」中按小组查看 L1 一线响应、L2 二线升级、L3 部门升级、L4 兜底通知。显示实际升级间隔；人员页提供「排班与升级通知」入口。

`roster.member.add/remove` 映射到 `set_roster`，后端先读取并校验完整快照，只修改目标小组、级别及范围。默认名单操作保留日期覆盖；今日操作仅写入当前业务日期的目标级别，首次覆盖时复制当前有效成员，避免丢失其他人。跨日提交拒绝，默认/今日广播或未知特殊级别只读。姓名和企微人员 ID 为新增参数，删除仅从本级名单移除；不添加或移除群成员。

保留所有其他日期、小组、专员和楼栋时段数据，以及未修改人员的附加字段；沿用角色、租户、版本冲突及结果不明防重试机制。名单不代表实时在岗，排班和升级执行仍由远端业务引擎负责。真实端点只读确认三个小组的 L3 均为 `@ALL`；新增写入仅经模拟 MCP 验证，未操作真实通知名单。
