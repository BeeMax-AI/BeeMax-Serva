# 列表界面审查与优化（2026-09-06）

本轮范围：排班页面内容过长、分页不一致，以及相关列表的筛选、焦点和信息密度。未修改业务接口或客户数据。

| 检查发现 | 已完成调整 |
|---|---|
| 配置排班、路由、审计记录一次全部铺开 | 增加搜索、适用的小组/档位筛选及统一分页 |
| 人员页有 20/30 条，工单/消息仍是 8 条 | 共用分页实现，默认 20 条，可选 30 条；显示总数、当前范围、页码 |
| 账号、授权群列表未分页 | 加入同一分页控件；MCP 未提供这些数据时仍展示不可用状态 |
| 报告历史和计划数量增加后页面无限增长 | 历史报告独立分页；首页只预览 6 个计划；完整管理弹窗独立分页与有限高度 |
| 标签切换/筛选会保留过期页码 | 切换配置标签清除旧筛选并回第一页，过滤/删除后页码自动收敛 |
| 中文输入每个组合输入事件都重绘 | 组合输入期间不重绘，上屏后查询；恢复输入位置 |
| 下拉筛选和翻页后焦点丢失 | 下拉恢复控件焦点，翻页聚焦对应列表标题并滚动定位 |
| 只读排班显示编辑按钮且列名“在岗”有歧义 | 显示“仅查看”和“排班说明”，移除只读模式的逐行编辑列 |
| 数据说明占据首屏；历史报告使用 LATEST 标识 | 数据说明按需展开，部分数据仍在摘要显著说明；统一使用“分析报告” |
| 只读用户无法查看被截断的计划 | 所有角色可打开完整计划列表，只有写操作受角色限制 |

分页条数在当前打开的工作台内共用，重新加载后默认 20；不同页面和配置标签切换回第一页，报告/计划管理各自维护独立页码。业务统计仍覆盖全部筛选结果，不按当前页计算。

验证：类型检查、构建、完整测试套件、品牌颜色检查通过。新增分页测试覆盖 65 条配置记录的首末页、20/30 切换、筛选收敛、空结果、独立页码和只读入口。真实浏览器验证排班的 20/17 分页、30 条模式、档位筛选、标签重置、工单共享条数及计划管理控件。未向真实业务写入测试记录；未开放缺少 MCP 工具的功能。
